## 状态约定

- `try`：试用态（未登录）
- `auth`：登录态
- 试用态硬转化点：领导承受值归零倒地 → 必须登录才能复活

## P1 首页（主页）

> 页面文件：`../P1_首页.html`
> 定位：试用与登录共用的核心页。承载桌宠互动、下班倒计时、签到、吐槽墙、释怀入口、关怀提醒。

### 接口清单

> 约定：`try`=试用态（未登录，仅只读+桌宠本地互动）；`auth`=登录态（全功能）。
> 试用态硬转化点：领导承受值归零倒地 → 必须登录才能复活。

#### 1. 桌宠状态读取 — `auth`
```
GET /rpc/pet.get
```
返回当前登录用户的桌宠外观配置与状态。
- 响应体：
```json
{
  "appearance": { "version": 1, "face":0, "hair":1, "glasses":0, "beard":0, "expr":1, "suit":0, "belly":1, "skin":1 },
  "status": { "endure": 62, "irritate": 45, "fat": 30, "dirty": 18, "down": false, "locked_until": null },
  "nameplate": { "name": "暴躁打工人 · 领导", "sub": "再改一版，今晚就给" }
}
```
- `down=true` 时进入倒地待复活状态，前端禁用动作积分，仅播放补刀反馈。
- `locked_until` 为拍扁/爆炸/臭晕锁定结束时间戳；前端不得永久锁死。
- 试用态不调用此接口，前端使用预置领导（`appearance=null`，状态默认值）。

#### 2. 桌宠动作上报 — `auth`
```
POST /rpc/pet.act
```
客户端只上报"做了什么动作"，由服务端结算承受值/状态/积分。
- 请求体：
```json
{ "act": "poke|slap|feed|throw", "client_round_id": "uuid", "ts": 1730000000000 }
```
- `act` 动作类型，对应：戳一戳 / 拍一拍 / 喂饼 / 扔垃圾。
- `client_round_id` 一轮动作的幂等键，用于防重复结算。
- 响应体：
```json
{ "status": { "endure": 58, "irritate": 53, "fat": 30, "dirty": 18, "down": false, "locked_until": null },
  "points_delta": 10, "points_balance": 310, "rewarded": true }
```
- `rewarded=false` 表示已达上限或倒地补刀，不发积分。
- 服务端验证一轮动作上限与状态锁定；客户端本地即时反馈，可批量结算避免每次请求。
- 锁定期间（拍扁 5s / 爆炸 / 臭晕）重复点击不排队、不扣承受值、不发积分。

#### 3. 桌宠复活 — `auth`
领导 `down=true` 时触发。
```
POST /rpc/pet.revive
```
- 请求体：`{ "mode": "revive|reface" }`
  - `revive`：消耗 500 积分复活原领导，状态清零（承受值满、胖度/脏度/烦躁度清零），外观保留。
  - `reface`：免费重新捏脸，获得满承受值新领导，旧领导永久替换（前端须二次确认）。
- 响应体：`{ "ok": true, "points_balance": -190, "status": {...满血...} }`
- 积分不足时：`{ "ok": false, "reason": "insufficient_points" }`，前端引导去赚积分。

#### 4. 公开吐槽随机墙 — `try` + `auth`
```
GET /rpc/rants.random?limit=10
```
- 公开接口，不返回身份。响应体（数组）：
```json
[{ "id": "r_abc", "content": "周报三千字...", "votes": 142, "created_at": 1730000000, "expires_at": 1731296000 }]
```
- 不返回账号、所有者 ID、销毁凭证、审核信息。
- 实时排除已销毁和超过 15 天的内容。
- 纯随机，不按票数/时间/热度排序。
- `expires_at` 用于前端计算渐隐程度（发布起 15 天）。

#### 5. 发布吐槽 — `auth`
```
POST /rpc/rants.create
```
- 请求体：`{ "content": "1–50 字纯文本", "idempotency_key": "uuid" }`
- 前端预检：1–50 字、去首尾空格、压缩连续空白、敏感词即时反馈。
- 服务端复检为入库硬门槛：内容安全、隐私信息（手机/邮箱/微信/身份证/地址/工号）、每日 3 条上限。
- 响应体：`{ "ok": true, "rant": {...}, "points_delta": 50, "remaining_today": 2 }`
- 失败：`{ "ok": false, "reason": "sensitive|limit_exceeded|invalid" }`
- 发布超时不得自动无限重试；保留输入。

#### 6. 共鸣 — `auth`
```
POST /rpc/resonance.create
```
- 请求体：`{ "rant_id": "r_abc" }`
- 约束：同一账号对同一条只能一次；作者不能给自己共鸣；已销毁/淡忘内容不接受。
- 响应体：`{ "ok": true, "clicker_points_delta": 10, "clicker_rewarded_today": 5, "clicker_reward_cap": 10, "votes": 143 }`
- 点击者每日前 10 次得 +10，第 11 次起 `clicker_points_delta=0`。
- 乐观更新失败时回滚前端 votes。
- 作者收益为待领取（不在此接口即时发放，见 P4 收下共鸣）。

#### 7. 签到 — `auth`
```
POST /rpc/checkin.sign
```
- 每个服务端自然日一次。
- 请求体：`{ "client_date": "2026-08-14" }`（仅参考，以服务端自然日为准）
- 响应体：
```json
{ "ok": true, "base": 100, "surprise": 0, "surprise_label": "普通",
  "streak": 6, "streak_bonus": 0, "points_delta": 100, "points_balance": 400,
  "longest_streak": 12, "already_signed": false }
```
- 随机惊喜概率：普通 50%(+0) / 小惊喜 30%(+10) / 中惊喜 15%(+20) / 大惊喜 5%(+50)。
- 里程碑：连续 3 天 +100、7 天 +300、14 天 +600，之后每 7 天 +300。
- 自然保护：连续 5 天无惊喜，第 6 天至少 +10（前台不展示保底措辞）。
- `already_signed=true` 时不发分，前端显示"今日已签到"。

#### 8. 签到状态 — `auth`
```
GET /rpc/checkin.status
```
- 响应体：`{ "signed_today": false, "streak": 5, "longest_streak": 12, "next_milestone": 7, "today_points": 50 }`

#### 9. 关怀提醒完成 — `auth`
```
POST /rpc/care.complete
```
- 请求体：`{ "type": "water|sit" }`
- 用户点击即视为完成，不调用摄像头/传感器/运动数据。
- 响应体：`{ "ok": true, "points_delta": 20, "today_count": 3, "today_cap": 6 }`
- 喝水 +20（每天前 6 次）、久坐 +30（每天前 4 次）；达上限后 `points_delta=0` 但提醒仍可用。
- 忽略、关闭或超时不发积分；页面关闭期间不补积分；设备休眠恢复最多补显示一次。

#### 10. 下班倒计时（纯前端，无接口）
- 用户只设置下班时间（默认 18:00），存本地（登录后存 profiles）。
- 进度从当天首次打开页面起算：首次打开为 0%，下班为 100%，线性比例。
- 每秒按当前时间重新计算；后台恢复不得依靠累计计时漂移。
- 过下班时间显示 100% 和共情文案（心疼语气，随机）。
- 登录态如需保存下班时间：
```
PUT /rpc/profile.offtime
{ "off_hour": 18, "off_min": 0 }
```

#### 11. 试用态权益预览（无接口）
- 试用态不产生正式积分；前端展示"登录后本次可得 +X"作为权益预览。
- 登录后不补发试用积分。

## 接口通用约定

### 安全硬门槛（前端必须遵守，后端必须强校验）

1. **公开接口不泄露身份**：公开吐槽查询只返回 `id / content / votes / created_at / expires_at`，绝不返回账号、所有者 ID、销毁凭证或内部审核信息。
2. **吐槽展示用安全纯文本**：前端渲染必须做文本转义，禁止 HTML 注入。
3. **客户端不直接结算积分**：客户端只能上报行为（如"我戳了一次桌宠"），由服务端根据行为类型和配置结算分值；客户端不得提交"给我 +10"。
4. **积分事件必须带唯一事件键**（idempotency key），网络重试不得重复发放。
5. **共鸣记录必须有 账号+吐槽 唯一约束**，防重复共鸣。
6. **查询实时排除已销毁和过期内容**，不能只依赖定时清理；公开原文最长保存 15 天。
7. **限流**：注册、登录、找回、发布、共鸣、销毁、积分结算均需限流。
8. **密码与恢复码**：密码用成熟哈希算法；恢复码只存哈希；任何日志不得记录密码或恢复码。

### 数据域划分（对应后端表结构建议）

| 数据域 | 主要内容 | 访问边界 |
|--------|---------|---------|
| profiles | 积分余额、签到、提醒、桌宠配置与状态 | 仅本人读写，关键字段服务端结算 |
| rants | 公开内容、时间、销毁状态 | 公开仅返回必要字段；仅所有者可销毁 |
| resonances | 吐槽、点击者、作者奖励状态 | 唯一约束防重复；公开不返回身份 |
| point_ledger | 积分事件、数值、唯一事件键、创建时间 | 只读本人记录；客户端不能指定奖励值 |
| auth | 账号、密码哈希、恢复码哈希 | 与业务数据隔离；严格限流 |

### 接口原则

- 浏览器不直接获得任意表写权限；发布经 Edge Function，随机查询与修改走受限 RPC/函数。
- 桌宠连续动作可本地即时反馈并批量结算，避免每次点击都请求；服务端验证一轮上限和状态。
- 网络不可用时桌宠本地动画和倒计时可运行；投稿、共鸣、签到和积分结算提示重试。
- 发布超时不得自动无限重试；保留输入；使用幂等请求 ID 避免重复内容。
- 共鸣乐观更新失败时回滚；销毁失败时保留内容和操作资格。

### 时间相关

- 所有"每日""每日上限"以**服务端自然日**为准。
- 下班倒计时进度从当天首次打开页面起算；每秒按当前时间重新计算；后台恢复后不得依靠累计计时产生漂移。
- 释怀加分条件：吐槽发布满 24 小时且完整看完动画（不跳过）。

### 字段口径

- 账号字段统一称"账号"，趣味文案可称"牛马编号""摸鱼代号"，但不得暗示填写真实工号。
- 账号不在任何公共页面、接口或吐槽卡片中展示。
