# 小确闲 · 云端开发环境搭建说明

> 目标：不在本机安装 Docker、Node.js、Supabase CLI 或数据库；使用 GitHub Codespaces 与 Supabase Cloud 开发项目完成 M0–M7。

## 1. 用户需要在浏览器完成的准备

1. 注册或登录 GitHub，开启多因素认证；
2. 注册或登录 Supabase，开启多因素认证；
3. 创建 GitHub **私有仓库**：建议命名 `xqx`；
4. 在 Supabase 创建开发项目：建议命名 `xqx-dev`；
5. 不要在聊天、仓库、HTML 或截图中保存任何密钥。

仓库创建和 Supabase 项目创建会改变你的外部账号状态；在执行这两个操作前由你在浏览器确认即可。

## 2. 已为 Codespaces 准备的项目文件

| 文件 | 作用 |
|---|---|
| `.devcontainer/devcontainer.json` | 指定 Node 22 云端容器、编辑器扩展、端口转发与初始化检查 |
| `package.json` | 统一前端预览、静态检查和 Supabase CLI 命令 |
| `scripts/check-static.mjs` | 检查 P1–P6、M0 迁移、安全标记和明显的明文密钥 |
| `.github/workflows/static-check.yml` | 每次推送/PR 自动执行静态基线检查 |

## 3. 创建 Codespaces 后的第一次验证

在仓库页面选择 `Code → Codespaces → Create codespace on main`。环境创建完成后，在其终端执行：

```bash
npm run check:static
npm run dev
```

Codespaces 会转发 4173 端口。打开预览链接后，应能访问 `P1_首页.html` 并跳转至 P2–P6。

Supabase CLI 不需在本机安装，可在 Codespaces 中使用：

```bash
npm run supabase -- --version
```

## 4. 连接 `xqx-dev` 的密钥处理

后续需要的公开连接配置：

```text
SUPABASE_URL
SUPABASE_ANON_KEY
```

只将其存入 Codespaces Secrets 或开发环境专用 `.env.local`（根目录 `.gitignore` 已忽略此类文件）。

以下密钥只允许存在于 Supabase Edge Function Secrets，不进入前端和 Codespaces 通用环境：

```text
SUPABASE_SERVICE_ROLE_KEY
RECOVERY_CODE_PEPPER
RATE_LIMIT_SECRET
CONTENT_MODERATION_API_KEY
```
