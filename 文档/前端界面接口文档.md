## 状态约定

- `try`：试用态（未登录）
- `auth`：登录态
- 试用态硬转化点：领导承受值归零倒地 → 必须登录才能复活

## P1 首页（主页）

> 页面文件：`../P1_首页.html`
> 定位：试用与登录共用的核心页。承载桌宠互动、下班倒计时、签到、吐槽墙、释怀入口、关怀提醒。

### 接口清单

当前真实接入的登录态资料接口为 `POST /functions/v1/profile-me`；它返回账号展示名、积分、DIY 权益、外观、桌宠状态、真实连续签到天数和签到日期。P1/P2 的桌宠独立读取使用 `POST /functions/v1/pet-get`。页面不得用静态示例值覆盖这些字段。

> 约定：`try`=试用态（未登录，仅只读+桌宠本地互动）；`auth`=登录态（全功能）。
> 试用态硬转化点：领导承受值归零倒地 → 必须登录才能复活。

#### 1. 桌宠状态读取 — `auth`
```
POST /functions/v1/pet-get
```
返回当前登录用户的桌宠外观配置与状态，并返回 `free_diy_available` 和由服务端计算的 `will_revive_on_save`。
- 响应体：
```json
{
  "appearance": { "version": 1, "face":0, "hair":1, "glasses":0, "beard":0, "expr":1, "suit":0, "belly":1, "skin":1 },
  "status": { "endure": 62, "irritate": 45, "fat": 30, "dirty": 18, "down": false, "locked_until": null },
  "nameplate": { "name": "暴躁打工人 · 领导", "sub": "再改一版，今晚就给" }
}
```
- `down=true` 时进入倒地待复活状态，前端禁用动作积分，仅播放补刀反馈。
- `locked_until` 为拍扁/爆炸/臭晕锁定结束时间戳；前端不得永久锁死。
- 试用态不调用此接口，前端使用预置领导（`appearance=null`，状态默认值）。

#### 2. 桌宠动作上报 — `auth`
```
POST /rpc/pet.act
```
客户端只上报"做了什么动作"，由服务端结算承受值/状态/积分。
- 请求体：
```json
{ "act": "poke|slap|feed|throw", "client_round_id": "uuid", "ts": 1730000000000 }
```
- `act` 动作类型，对应：戳一戳 / 拍一拍 / 喂饼 / 扔垃圾。
- `client_round_id` 一轮动作的幂等键，用于防重复结算。
- 响应体：
```json
{ "status": { "endure": 58, "irritate": 53, "fat": 30, "dirty": 18, "down": false, "locked_until": null },
  "points_delta": 10, "points_balance": 310, "rewarded": true }
```
- `rewarded=false` 表示已达上限或倒地补刀，不发积分。
- 服务端验证一轮动作上限与状态锁定；客户端本地即时反馈，可批量结算避免每次请求。
- 锁定期间（拍扁 5s / 爆炸 / 臭晕）重复点击不排队、不扣承受值、不发积分。

#### 3. 桌宠复活 — `auth`
领导 `down=true` 时触发。
```
POST /rpc/pet.revive
```
- 请求体：`{ "mode": "revive|reface" }`
  - `revive`：消耗 500 积分复活原领导，状态清零（承受值满、胖度/脏度/烦躁度清零），外观保留。
  - `reface`：免费重新捏脸，获得满承受值新领导，旧领导永久替换（前端须二次确认）。
- 响应体：`{ "ok": true, "points_balance": -190, "status": {...满血...} }`
- 积分不足时：`{ "ok": false, "reason": "insufficient_points" }`，前端引导去赚积分。

#### 4. 公开吐槽随机墙 — `try` + `auth`
```
GET /rpc/rants.random?limit=10
```
- 公开接口，不返回身份。响应体（数组）：
```json
[{ "id": "r_abc", "content": "周报三千字...", "votes": 142, "created_at": 1730000000, "expires_at": 1731296000 }]
```
- 不返回账号、所有者 ID、销毁凭证、审核信息。
- 实时排除已销毁和超过 15 天的内容。
- 纯随机，不按票数/时间/热度排序。
- `expires_at` 用于前端计算渐隐程度（发布起 15 天）。

#### 5. 发布吐槽 — `auth`
```
POST /rpc/rants.create
```
- 请求体：`{ "content": "1–50 字纯文本", "idempotency_key": "uuid" }`
- 前端预检：1–50 字、去首尾空格、压缩连续空白、敏感词即时反馈。
- 服务端复检为入库硬门槛：内容安全、隐私信息（手机/邮箱/微信/身份证/地址/工号）、每日 3 条上限。
- 响应体：`{ "ok": true, "rant": {...}, "points_delta": 50, "remaining_today": 2 }`
- 失败：`{ "ok": false, "reason": "sensitive|limit_exceeded|invalid" }`
- 发布超时不得自动无限重试；保留输入。

#### 6. 共鸣 — `auth`
```
POST /rpc/resonance.create
```
- 请求体：`{ "rant_id": "r_abc" }`
- 约束：同一账号对同一条只能一次；作者不能给自己共鸣；已销毁/淡忘内容不接受。
- 响应体：`{ "ok": true, "clicker_points_delta": 10, "clicker_rewarded_today": 5, "clicker_reward_cap": 10, "votes": 143 }`
- 点击者每日前 10 次得 +10，第 11 次起 `clicker_points_delta=0`。
- 乐观更新失败时回滚前端 votes。
- 作者收益为待领取（不在此接口即时发放，见 P4 收下共鸣）。

#### 7. 举报公开吐槽 — `auth`
```
POST /functions/v1/rant-report
```
- 请求体：`{ "rant_id": "uuid", "reason": "privacy|abuse|other", "request_id": "uuid" }`。
- 仅登录用户可举报；不能举报自己、同一用户对同一内容只能举报一次。举报者身份和举报原因不出现在公开墙或吐槽作者页面。
- 达到服务端配置的不同用户举报阈值（当前为 3）后，仅将 `review_status` 置为 `hidden`，随机墙实时排除；原记录保留给受控人工核查，不自动物理删除。

#### 7. 签到 — `auth`
```
POST /rpc/checkin.sign
```
- 每个服务端自然日一次。
- 请求体：`{ "client_date": "2026-08-14" }`（仅参考，以服务端自然日为准）
- 响应体：
```json
{ "ok": true, "base": 100, "surprise": 0, "surprise_label": "普通",
  "streak": 6, "streak_bonus": 0, "points_delta": 100, "points_balance": 400,
  "longest_streak": 12, "already_signed": false }
```
- 随机惊喜概率：普通 50%(+0) / 小惊喜 30%(+10) / 中惊喜 15%(+20) / 大惊喜 5%(+50)。
- 里程碑：连续 3 天 +100、7 天 +300、14 天 +600，之后每 7 天 +300。
- 自然保护：连续 5 天无惊喜，第 6 天至少 +10（前台不展示保底措辞）。
- `already_signed=true` 时不发分，前端显示"今日已签到"。

#### 8. 签到状态 — `auth`
```
GET /rpc/checkin.status
```
- 响应体：`{ "signed_today": false, "streak": 5, "longest_streak": 12, "next_milestone": 7, "today_points": 50 }`

#### 9. 关怀提醒完成 — `auth`
```
POST /rpc/care.complete
```
- 请求体：`{ "type": "water|sit" }`
- 用户点击即视为完成，不调用摄像头/传感器/运动数据。
- 响应体：`{ "ok": true, "points_delta": 20, "today_count": 3, "today_cap": 6 }`
- 喝水 +20（每天前 6 次）、久坐 +30（每天前 4 次）；达上限后 `points_delta=0` 但提醒仍可用。
- 忽略、关闭或超时不发积分；页面关闭期间不补积分；设备休眠恢复最多补显示一次。

#### 10. 下班倒计时（纯前端，无接口）
- 用户只设置下班时间（默认 18:00），存本地（登录后存 profiles）。
- 进度从当天首次打开页面起算：首次打开为 0%，下班为 100%，线性比例。
- 每秒按当前时间重新计算；后台恢复不得依靠累计计时漂移。
- 过下班时间显示 100% 和共情文案（心疼语气，随机）。
- 登录态如需保存下班时间：
```
PUT /rpc/profile.offtime
{ "off_hour": 18, "off_min": 0 }
```

当前实现改为登录态 Edge Function：`POST /functions/v1/work-preferences-save`，请求为 `{ "off_hour": 18, "off_min": 0, "water_interval": 60, "sit_interval": 45 }`。两个间隔只允许 `30`、`45`、`60`、`90` 分钟；成功后由服务端保存至当前账号，`profile-me` 在后续登录时返回该设置。

#### P1 当前已接入的 Supabase Functions

| 功能 | Function | 关键约束 |
|---|---|---|
| 登录态资料 | `profile-me` | 必须带 Bearer JWT；返回账号、积分、权益、桌宠状态和签到摘要 |
| 签到 | `checkin-sign` | 服务端自然日唯一；重复请求返回 `already_signed`，不得重复加分 |
| 桌宠动作 | `pet-action` | 请求 `{ action, request_id }`；积分和状态由服务端事务结算 |
| 复活领导 | `pet-revive` | 请求 `{ request_id }`；仅倒地状态可复活，服务端扣除配置积分并恢复状态 |
| 随机吐槽墙 | `rants-random` | 匿名可读；只返回 `id/content/votes/created_at/expires_at` |
| 发布吐槽 | `rants-create` | 登录态；服务端检查长度、明显联系方式、每日上限和 +50 积分幂等结算 |
| 共鸣 | `resonance-create` | 登录态；不能共鸣自己的吐槽，同一吐槽只能一次，每日前 10 次奖励 |

`pet-action` 的 `action` 只能是 `poke`、`slap`、`feed`、`throw`。失败原因包括 `pet_down`、`pet_locked`、`invalid_action` 和 `invalid_session`。前端收到成功响应后，以返回的 `pet_status` 与 `points_balance` 覆盖本地状态，不得自行计算正式积分。

当 `pet_status.down=true` 时，P1 必须持续显示倒地状态和“复活 / 重新捏领导”操作区；登录或刷新页面不能隐式复活。动作反馈同时要作用于当前可见的人物预览，不能只调用隐藏的渲染器动画。

#### 11. 试用态权益预览（无接口）
- 试用态不产生正式积分；前端展示"登录后本次可得 +X"作为权益预览。
- 登录后不补发试用积分。

## P2 捏脸DIY

P2 已接入 `pet-get` 和 `profile-save-appearance`。保存请求必须为 `{ "appearance": {...}, "request_id": "uuid" }`：首次保存消耗一次免费 DIY；若 `pet_status.down=true`，这次保存将由服务端同时重新捏领导并恢复满血。正常已保存领导不得进入 P2 调整外观；P2 可保留本地预览，但最终状态必须以服务器响应为准。

## P3 释怀仪式

- 释怀不是独立的内容创建模块，而是“匿名发声”的后续操作。用户在 P4「我的吐槽」中，对一条本人已发布的匿名发声点击“选择释怀方式”后进入 P3，并通过 `rant_id` 预选该内容。
- 选择已有吐槽后调用 `POST /functions/v1/release-complete`：`{ "rant_id": "uuid", "request_id": "uuid" }`。服务端先完成销毁，再根据配置的最小发布时间决定是否发放 +100；动画和结果文案以响应为准。
- P3 只展示本人状态为 `published` 的内容；没有可选内容时提示先发布匿名发声。P3 不提供手写输入，也不调用 `release-draft`，以避免与匿名发声形成两套内容来源。
- 用户选择风吹散、揉成团或碎纸机后，三种方式使用同一个 `release-complete` 原子销毁接口；方式仅影响前端动画，不改变积分规则。
- 页面不再使用 `?fresh=1` 或其他前端参数模拟新旧吐槽，重复点击同一个请求键必须返回原结算结果。

## P4 个人中心

当前实现通过 `POST /functions/v1/profile-me` 读取账号、积分、DIY 权益、连续签到和签到日历；修改密码、退出登录和恢复码展示已接入 M1。个人中心的账号名称、连续签到徽章和签到日历必须来自云端返回值，禁止保留“我的小确闲”“连续签到 7 天”这类静态占位数据。

## P5 找回密码

### M1 联调实现（2026-08-18）

- 调用 `POST /functions/v1/auth-reset-password`，请求字段为 `account`、`recovery_code`、`new_password`、`request_id`；
- 仅在成功响应中展示服务端返回的新恢复码；前端不得生成、猜测或缓存恢复码；
- `429 rate_limited` 显示服务端返回的等待秒数；`401 invalid_recovery` 显示统一提示，不枚举具体失败原因；
- 密码、恢复码、会话 Token 不写入页面、URL、日志或 Toast。

## M1 浏览器公共配置

三个页面通过 `scripts/xqx-auth.js` 调用已部署的 Edge Functions，并由 `scripts/xqx-config.js` 提供公开连接配置。开发者只可填写：

```js
window.XQX_CONFIG = {
  supabaseUrl: "https://<project-ref>.supabase.co",
  supabaseAnonKey: "<anon-or-publishable-key>",
};
```

`supabaseAnonKey` 是浏览器可公开使用的匿名/发布密钥；绝不可填入 `SUPABASE_SERVICE_ROLE_KEY`、数据库密码、`RECOVERY_CODE_PEPPER` 或 `RATE_LIMIT_SECRET`。登录会话保存在当前浏览器的 `localStorage`，并在即将到期时使用刷新 Token 获取新会话。

## 接口通用约定

### 安全硬门槛（前端必须遵守，后端必须强校验）

1. **公开接口不泄露身份**：公开吐槽查询只返回 `id / content / votes / created_at / expires_at`，绝不返回账号、所有者 ID、销毁凭证或内部审核信息。
2. **吐槽展示用安全纯文本**：前端渲染必须做文本转义，禁止 HTML 注入。
3. **客户端不直接结算积分**：客户端只能上报行为（如"我戳了一次桌宠"），由服务端根据行为类型和配置结算分值；客户端不得提交"给我 +10"。
4. **积分事件必须带唯一事件键**（idempotency key），网络重试不得重复发放。
5. **共鸣记录必须有 账号+吐槽 唯一约束**，防重复共鸣。
6. **查询实时排除已销毁和过期内容**，不能只依赖定时清理；公开原文最长保存 15 天。
7. **限流**：注册、登录、找回、发布、共鸣、销毁、积分结算均需限流。
8. **密码与恢复码**：密码用成熟哈希算法；恢复码只存哈希；任何日志不得记录密码或恢复码。

### 数据域划分（对应后端表结构建议）

| 数据域 | 主要内容 | 访问边界 |
|--------|---------|---------|
| profiles | 积分余额、签到、提醒、桌宠配置与状态 | 仅本人读写，关键字段服务端结算 |
| rants | 公开内容、时间、销毁状态 | 公开仅返回必要字段；仅所有者可销毁 |
| resonances | 吐槽、点击者、作者奖励状态 | 唯一约束防重复；公开不返回身份 |
| point_ledger | 积分事件、数值、唯一事件键、创建时间 | 只读本人记录；客户端不能指定奖励值 |
| auth | 账号、密码哈希、恢复码哈希 | 与业务数据隔离；严格限流 |

### 接口原则

- 浏览器不直接获得任意表写权限；发布经 Edge Function，随机查询与修改走受限 RPC/函数。
- 桌宠连续动作可本地即时反馈并批量结算，避免每次点击都请求；服务端验证一轮上限和状态。
- 网络不可用时桌宠本地动画和倒计时可运行；投稿、共鸣、签到和积分结算提示重试。
- 发布超时不得自动无限重试；保留输入；使用幂等请求 ID 避免重复内容。
- 共鸣乐观更新失败时回滚；销毁失败时保留内容和操作资格。

### 时间相关

- 所有"每日""每日上限"以**服务端自然日**为准。
- 下班节奏以用户设置的下班时间向前推导 9 小时工作时段；每秒按当前时间重算，不依赖页面首次打开时间，后台恢复后不得产生累计漂移。
- 用户登录后不主动弹出工作节奏设置；系统读取云端下班、喝水和久坐偏好，并从本次登录时刻按对应间隔重新开始两个提醒倒计时。设置只能由用户点击首页“调整节奏”主动打开。
- 释怀加分条件：匿名发声发布满 24 小时且完整看完动画（不跳过）。

### P1/P4 真实数据接入（2026-08-18）

- P1 随机墙调用 `GET /functions/v1/rants-random?limit=9`；发布、共鸣、关怀分别调用 `rants-create`、`resonance-create`、`care-complete`，成功后必须以响应中的 `points_balance` 覆盖页面余额。
- P4 调用 `points-ledger`、`rants-mine` 和 `resonance-claim`；积分明细、我的吐槽和可领取共鸣不得使用静态数组或本地加分。
- P4 只展示仍处于 `published` 且未到期的匿名发声；已释怀、已拒绝或 15 天到期的内容不显示在“我的吐槽”中。服务端即使定时归档尚未执行，也必须实时按 `expires_at` 排除。
- 云端接口暂不可用时只显示加载失败/重试提示，禁止回退到示例吐槽、示例积分或假成功 Toast。

### P1 下班节奏与关怀提醒（2026-08-18）

- 首页不提供“试用态 / 登录态”人工切换器；登录状态只由真实会话恢复、登录或退出操作改变。
- 未签到时，桌宠右侧仅显示签到卡；签到成功后该位置替换为“下班航线”进度面板，显示按下班时间推导出的上班时间、实时工作进度和剩余时间。
- 下班设置弹窗同时设置喝水、久坐频率（30 / 45 / 60 / 90 分钟）。提醒只在已签到且处于工作时段时弹出；完成任务后从完成时刻重新计时。
- 倒地后的积分不足弹窗每次倒地只自动提醒一次；桌宠卡中的“复活 / 查看费用”仍可由用户主动再次打开。刷新页面、登录恢复或读取云端历史倒地状态时不得自动弹窗。

### P1/P2 外观入口与首次设置（2026-08-21）

- P1 必须以 `profile-me.appearance` 判断是否已有已保存领导：未保存时首页主入口为“开始捏领导”并进入 P2；已保存且正常时主入口为“开始暴揍领导”并定位至首页桌宠区。导航和页脚不得提供绕过状态的 P2 直链。
- P2 只服务于首次创建领导，或 `pet_status.down=true` 时的“重新捏领导”。页面加载必须再次读取 `profile-me` 与 `pet-get`：已有外观且领导未倒地时直接回到 `P1_首页.html#pet`；保存成功后同样回到该区域。该规则不能只依赖首页入口控制。
- 工作节奏设置仅由“调整节奏”主动打开；登录、刷新和会话恢复不得自动弹出。顶部导航不显示下班倒计时，签到后的下班航线面板仍保留完整的进度与剩余时间。
- P2 可见的 2D 捏脸选项必须独立于 Three.js/CDN 加载：外部 3D 渲染器只做增强预览，加载异常时脸型、发型、服装等选项仍必须可点击并同步 2D 人物预览。

### P1 登录视觉区（2026-08-18）

- 登录/注册弹窗采用圆角双栏布局：左侧为与“下班前片刻喘息”主题一致的动态视觉区，右侧为账号表单；移动端自动改为上下布局。
- 默认视觉是页面内置 CSS 动画插画，不依赖外部图片请求；可在 `scripts/xqx-config.js` 的 `XQX_AUTH_VISUAL.asset` 中替换为 GIF、WebP 或 PNG 路径。
- 替换素材不改变认证逻辑、错误提示、注册恢复码和弹窗行为；素材不可用时仍保留内置动画作为降级显示。

### 字段口径

- 账号字段统一称"账号"，趣味文案可称"牛马编号""摸鱼代号"，但不得暗示填写真实工号。
- 账号不在任何公共页面、接口或吐槽卡片中展示。
